# MemoryMesh Harness

[English](README.en.md)

MemoryMesh는 작업을 멈추거나 다른 에이전트로 바꿔도, 이전 상황을 처음부터 다시 설명하지 않고 이어갈 수 있도록 돕습니다.

- 작업을 중간에 멈췄다가 나중에 다시 이어서 할 때
- 사용 한도에 도달해 다른 에이전트에게 작업을 넘겨야 할 때
- 다른 에이전트에게 검토와 검증을 맡긴 뒤 그 결과를 반영해 계속 작업할 때

진행 상황과 결정, 검증 결과, 남은 작업을 프로젝트에 기록하고, 다음 세션이나 에이전트가 이를 읽어 반영하도록 합니다.

## 적용 방법

1. [memorymesh-setup.md](memorymesh-setup.md)를 내려받아 적용할 프로젝트의 최상위 폴더에 넣습니다.
2. 해당 폴더를 열고 에이전트에 다음과 같이 요청합니다.

```text
memorymesh-setup.md 파일의 설정 내용을 이 프로젝트에 적용하라.
```

Codex, Claude Code, Gemini CLI, Antigravity 등 프로젝트 파일을 읽고 저장할 수 있는 에이전트를 사용합니다. 기본 설치에는 별도 서버나 스킬 설치가 필요하지 않습니다.

처음 사용하거나 기존 구성을 변경할 때 모두 위 명령으로 시작합니다. 에이전트가 기존 설치와 버전, 기록을 확인하고, 확인 결과와 가능한 처리 방식을 보여준 뒤 원하는 방식을 한 번 묻습니다. 사용자는 안내된 선택지에서 원하는 처리 방식만 고르면 됩니다.

| 선택 | 처리 내용 |
|---|---|
| 신규 설치 | 필요한 기록과 지침을 구성합니다. |
| 기존 내용 유지하며 반영 | 기존 기록과 사용자 지침을 보존하며 갱신합니다. 기존 설치에 권장합니다. |
| 백업 후 초기화 설치 | 기존 MemoryMesh 구성을 백업한 뒤 다시 구성합니다. |
| MemoryMesh 제거 | 기록을 백업하고 MemoryMesh 전용 구성과 지침을 제거합니다. |
| 취소 | 변경 없이 종료합니다. |

초기화와 제거 시 프로젝트 자료, 사용자 지침의 다른 부분, 외부의 기존 업무 일지와 공용 도구는 보존합니다. 소유권이 불분명한 항목은 남겨 두고 알려줍니다.

새 셋업 파일로 바꾼 경우에도 위 명령으로 다시 적용하면 됩니다.

## 만들어지거나 바뀌는 파일

처리 방식을 고르면 에이전트가 작업 전에 만들거나 수정하거나 제거할 파일과 백업 위치를 간단히 알려줍니다. 작업이 길어지면 진행 단계와 지연 원인을 알리고, 진전이 없으면 계획이나 방법을 재검토합니다. 끝나면 실제 변경한 항목과 완료 여부를 알려줍니다.

프로젝트 안의 `.mesh/`에 설정과 기록을 보관합니다. 기존 파일이 있으면 사용자 내용과 기록을 보존하며 필요한 부분을 갱신합니다.

| 파일 또는 폴더 | 용도와 생성 조건 |
|---|---|
| `.mesh/CONFIG.md` | 사용할 업무 일지와 기록 설정을 보관합니다. |
| `.mesh/PROTOCOL.md` | 작업 기록과 재개에 관한 공통 지침을 보관합니다. |
| `.mesh/STATE.md` | 현재 진행 상황과 남은 작업을 정리합니다. |
| `.mesh/INSTALL.json` | 설치 구성을 기록해 나중에 갱신하거나 제거할 대상을 구분합니다. |
| 기존 업무 일지 또는 `.mesh/work.log` | 작업 이력을 기록합니다. 기존 일지를 우선 사용하고, 없을 때만 기본 일지를 만듭니다. |
| `AGENTS.md` | Codex, Antigravity 등 대부분의 에이전트가 읽는 공통 지침 연결입니다. 기존 파일이 있으면 MemoryMesh 안내를 추가하거나 갱신합니다. |
| `CLAUDE.md`, `GEMINI.md` | Claude Code와 Gemini CLI가 같은 공통 지침을 읽도록 연결합니다. 별도 지침 없이 `AGENTS.md`를 참조하는 짧은 연결 내용만 담으므로, 지침은 `AGENTS.md` 한 곳에서만 관리됩니다. 어느 에이전트에서 적용하든 항상 함께 준비하며, 기존 파일이 있으면 사용자 내용은 그대로 두고 연결 내용만 추가합니다. |
| `AGENTS.override.md` | 이미 있을 때만 MemoryMesh 안내를 추가합니다. 새로 만들지는 않습니다. |
| `.mesh/handoffs/` | 상세 인계 문서가 필요할 때만 만듭니다. |
| `.memorymesh-backups/` | 기존 파일을 변경할 때 백업을 보관하는 기본 위치입니다. 별도로 정한 백업 위치가 있으면 그 위치를 사용합니다. |

사용자가 이 파일들을 미리 만들거나 직접 편집할 필요는 없습니다. 부가 스킬 파일을 실제로 추가하는 경우에도 해당 경로를 함께 안내합니다.

## 사용

설치 후에는 평소처럼 작업을 요청하면 됩니다. 어느 에이전트에서 적용했든 Codex, Claude Code, Gemini CLI, Antigravity 등 다른 에이전트에서도 다시 적용하지 않고 바로 이어서 작업할 수 있습니다. 연결 상태가 의심되면 그 에이전트에서 위 적용 명령을 다시 실행해 확인하고 빠진 부분만 보완할 수 있습니다.

- 새 작업을 시작할 때 이전 기록을 읽고 결정과 제약을 반영합니다.
- 작업 중 중요한 진행 사항을 저장하고, 작업 결과를 답하기 전에 새로 생긴 내용을 기록합니다. 별도의 저장 지시를 반복할 필요는 없습니다.
- 기존 업무 일지가 있으면 그대로 사용합니다. 없으면 `.mesh/work.log`에 기록하며, 현재 상태는 `.mesh/STATE.md`에서 확인할 수 있습니다.

정보나 의견만 묻거나 답변 정리를 요청하면 파일을 바꾸지 않습니다. 파일 수정이나 작업 실행을 분명히 요청하면 해당 범위의 작업과 필요한 기록 갱신을 수행합니다. 지시와 질문이 섞여 있으면 지시한 부분만 실행합니다.

## 주의할 점과 한계

- 저장된 기록을 바탕으로 작업을 재개하므로, 갑작스러운 종료 직전에 저장되지 않은 내용은 이어받지 못할 수 있습니다.
- 에이전트가 프로젝트 지침을 읽지 못하거나 파일 저장이 차단된 환경에서는 자동 기록과 재개가 제한될 수 있습니다.
- 도구가 실행되는 동안에는 에이전트가 진행 안내를 보내지 못해 안내가 늦어질 수 있습니다.
- 적용할 때는 현재 사용 중인 에이전트의 지침 로딩만 확인할 수 있습니다. 다른 에이전트용 연결 파일은 준비해 두며, 실제 로딩은 그 에이전트에서 처음 사용할 때 확인됩니다.
- 에이전트 설정에서 프로젝트 지침 로딩을 끄거나 지침 파일 이름을 바꿔 둔 경우에는 연결 파일이 있어도 자동으로 읽히지 않습니다. 이때는 에이전트에게 `.mesh/PROTOCOL.md`를 읽고 따르라고 한 번 요청하면 됩니다.
- 검증된 외부 스킬 원본을 내려받는 부가 기능은 사용자가 허락할 때만 실행합니다. 기본 기능은 내려받기 없이 동작합니다.
