# MemoryMesh Harness

[English](README.en.md)

MemoryMesh는 여러 세션과 에이전트, 컴퓨터를 오가는 작업을 끊김 없이 이어가게 하는 프로젝트용 작업 연속성 셋업입니다. 세션을 끝내거나 다른 에이전트, 다른 운영 체제로 옮겨도 이전 상황을 다시 설명하지 않고 하던 작업을 바로 이어갈 수 있습니다.

진행 상황과 결정, 검증 결과, 남은 작업을 프로젝트 안의 파일에 기록하고, 다음 세션이나 에이전트가 이를 읽어 반영합니다.

## 특징

- 파일 기반 기록: 작업 일지 하나와 현재 상태 요약, 필요할 때만 만드는 인계 문서로 구성됩니다. 별도 서버나 데이터베이스가 없습니다.
- 모든 에이전트에 같은 지침: `AGENTS.md`를 공통 지침으로 두고 `CLAUDE.md`와 `GEMINI.md`는 이를 참조만 하므로, Codex, Claude Code, Gemini CLI, Antigravity 등이 같은 지침과 기록을 사용합니다.
- 가벼운 지침 구조: 모든 작업에 적용하는 핵심 지침만 매번 읽고, 검토, 디버깅, 테스트 같은 절차는 해당 작업에서만 읽습니다.
- 하나의 적용 명령: 설치, 갱신, 초기화, 제거를 같은 요청으로 시작하며, 처리 방식은 한 번만 고릅니다.
- 의존성 없음: 기본 기능은 파일 읽기와 쓰기만으로 동작하며 셸, Git, Python, Node.js, 계정이나 플러그인이 필요하지 않습니다.

## 장점

- 세션이 끝나도 작업 결과뿐 아니라 대화 속에서 정한 결정, 확인 결과, 합의한 다음 단계까지 이어집니다.
- 다른 에이전트에서 셋업을 다시 적용하지 않고 같은 기록으로 바로 이어갑니다.
- 다른 운영 체제에서도 기록을 그대로 쓸 수 있고, 어떤 검증을 다시 해야 하는지 알 수 있습니다.
- 기록 없이 끝난 세션의 파일 변경은 다음 시작 때 확인해 보완합니다.
- 질문이나 검토 요청에서는 프로젝트 파일을 바꾸지 않고, 요청한 범위의 작업만 수행합니다.
- 불필요한 재확인과 반복 검증을 줄이고, 결과 보고에는 필요한 내용만 담습니다.
- 기존 업무 일지와 사용자 지침을 보존하고, 변경 전 백업을 남깁니다.

## 이런 경우에 사용합니다

- 하나의 작업을 며칠에 걸쳐 여러 세션으로 진행할 때
- 사용 한도나 비용 때문에 여러 에이전트를 오가며 작업할 때
- 한 운영 체제에서 시작한 작업을 다른 운영 체제에서 이어갈 때
- 긴 빌드나 대량 편집 도중 세션이 끊겼다가 다시 시작할 때
- 대화가 길어져 문맥이 압축되거나 새 세션을 열어야 할 때
- 논의로 방향을 정해 두고 나중에 실행할 때
- 다른 에이전트에게 검토나 검증을 맡기고 그 결과를 반영해 계속 작업할 때
- 여러 하위 프로젝트가 각자 독립된 기록을 유지해야 할 때

## 적용 방법

1. [memorymesh-setup.md](memorymesh-setup.md)를 내려받아 적용할 프로젝트의 최상위 폴더에 넣습니다.
2. 해당 폴더를 열고 에이전트에 다음과 같이 요청합니다.

```text
memorymesh-setup.md 파일의 설정 내용을 이 프로젝트에 적용하라.
```

Codex, Claude Code, Gemini CLI, Antigravity 등 프로젝트 파일을 읽고 저장할 수 있는 에이전트를 사용합니다. 기본 설치에는 별도 서버나 스킬 설치가 필요하지 않습니다.

처음 사용하거나 기존 구성을 변경할 때 모두 위 명령으로 시작합니다. 에이전트가 기존 설치와 버전, 기록을 확인하고, 확인 결과와 가능한 처리 방식을 보여준 뒤 원하는 방식을 한 번 묻습니다. 사용자는 안내된 선택지에서 원하는 처리 방식만 고르면 됩니다.

| 선택 | 처리 내용 |
|---|---|
| 신규 설치 | 필요한 기록과 지침을 구성합니다. |
| 기존 내용 유지하며 반영 | 기존 기록과 사용자 지침을 보존하며 갱신합니다. 기존 설치에 권장합니다. |
| 백업 후 초기화 설치 | 기존 MemoryMesh 구성을 백업한 뒤 다시 구성합니다. |
| MemoryMesh 제거 | 기록을 백업하고 MemoryMesh 전용 구성과 지침을 제거합니다. |
| 취소 | 변경 없이 종료합니다. |

적용할 때 MemoryMesh 블록 밖의 기존 사용자 지침이 새 지침과 겹치거나 충돌하면 수정하지 않고 알려줍니다. 초기화와 제거 시 프로젝트 자료, 사용자 지침의 다른 부분, 외부의 기존 업무 일지와 공용 도구는 보존합니다. 소유권이 불분명한 항목은 남겨 두고 알려줍니다.

새 셋업 파일로 바꾼 경우에도 위 명령으로 다시 적용하면 됩니다. 파일을 내려받거나 교체하는 것만으로 기존 프로젝트의 지침이 갱신되지는 않습니다. 기존 설치에서는 “기존 내용 유지하며 반영”을 선택하면 기록을 보존하면서 새 지침을 적용할 수 있습니다.

## 만들어지거나 바뀌는 파일

처리 방식을 고르면 에이전트가 작업 전에 만들거나 수정하거나 제거할 파일과 백업 위치를 간단히 알려줍니다. 작업이 길어지면 진행 단계와 지연 원인을 알리고, 진전이 없으면 계획이나 방법을 재검토합니다. 끝나면 실제 변경한 항목과 완료 여부를 알려줍니다.

프로젝트 안의 `.mesh/`에 설정과 기록을 보관합니다. 기존 파일이 있으면 사용자 내용과 기록을 보존하며 필요한 부분을 갱신합니다.

| 파일 또는 폴더 | 용도와 생성 조건 |
|---|---|
| `.mesh/CONFIG.md` | 사용할 업무 일지와 기록 설정을 보관합니다. |
| `.mesh/PROTOCOL.md` | 모든 작업에 적용하는 기록과 재개의 핵심 지침을 보관합니다. 작업을 시작할 때마다 읽으므로 짧게 유지합니다. |
| `.mesh/PROCEDURES.md` | 코드 검토, 디버깅, 테스트, 화면 검증처럼 특정 작업에만 필요한 절차를 보관합니다. 해당 작업에서만 읽습니다. |
| `.mesh/STATE.md` | 현재 진행 상황과 남은 작업을 정리합니다. |
| `.mesh/INSTALL.json` | 설치 구성을 기록해 나중에 갱신하거나 제거할 대상을 구분합니다. |
| 기존 업무 일지 또는 `.mesh/work.log` | 작업 이력을 기록합니다. 기존 일지를 우선 사용하고, 없을 때만 기본 일지를 만듭니다. |
| `AGENTS.md` | Codex, Antigravity 등 대부분의 에이전트가 읽는 공통 지침 연결입니다. 기존 파일이 있으면 MemoryMesh 안내를 추가하거나 갱신합니다. |
| `CLAUDE.md`, `GEMINI.md` | Claude Code와 Gemini CLI가 같은 공통 지침을 읽도록 연결합니다. 별도 지침 없이 `AGENTS.md`를 참조하는 짧은 연결 내용만 담으므로, 지침은 `AGENTS.md` 한 곳에서만 관리됩니다. 어느 에이전트에서 적용하든 항상 함께 준비하며, 기존 파일이 있으면 사용자 내용은 그대로 두고 연결 내용만 추가합니다. |
| `AGENTS.override.md` | 이미 있을 때만 MemoryMesh 안내를 추가합니다. 새로 만들지는 않습니다. |
| `.mesh/handoffs/` | 상세 인계 문서가 필요할 때만 만듭니다. |
| `.memorymesh-backups/` | 기존 파일을 변경할 때 백업을 보관하는 기본 위치입니다. 별도로 정한 백업 위치가 있으면 그 위치를 사용합니다. |

사용자가 이 파일들을 미리 만들거나 직접 편집할 필요는 없습니다. 부가 스킬 파일을 실제로 추가하는 경우에도 해당 경로를 함께 안내합니다.

## 사용

설치 후에는 평소처럼 작업을 요청하면 됩니다. 어느 에이전트에서 적용했든 Codex, Claude Code, Gemini CLI, Antigravity 등 다른 에이전트에서도 다시 적용하지 않고 바로 이어서 작업할 수 있습니다. 에이전트가 이전 작업 내용을 모르는 것 같으면 그 에이전트에서 위 적용 명령을 다시 실행하세요. 연결을 확인해 빠진 부분을 보완하고, 에이전트 설정 때문에 연결되지 않는 것이 확인되면 그 이유를 알려 줍니다.

- 새 작업을 시작할 때 이전 기록을 읽고 결정과 제약을 반영합니다.
- 오래 걸리거나 중단될 수 있는 작업 전에 진행 상황을 저장하고, 작업 결과를 답하기 전에 새로 생긴 내용을 한 번 기록합니다. 별도의 저장 지시를 반복할 필요는 없습니다.
- 기록 속 경로는 프로젝트 기준 상대 경로로 쓰고, 기록과 검증 결과에 실행한 에이전트와 운영 체제를 함께 남겨 다른 운영 체제에서도 그대로 이어받을 수 있게 합니다.
- 파일만으로는 알 수 없는 사용자 결정, 확인 결과, 합의한 다음 단계는 세션이 끝나도 사라지지 않도록 생긴 때에 짧게 기록합니다.
- 결과 보고에는 요청한 결과와 필요한 근거, 결과 판단에 영향을 주는 한계만 담고, 기록 내용을 답변에 옮겨 적지 않습니다.
- 상위 폴더에도 MemoryMesh가 설치되어 있으면 작업하는 파일에서 가장 가까운 폴더의 기록을 사용하고, 각 설치는 서로 독립적으로 유지합니다.
- 기존 업무 일지가 있으면 그대로 사용합니다. 없으면 `.mesh/work.log`에 기록하며, 현재 상태는 `.mesh/STATE.md`에서 확인할 수 있습니다.

포니테일, 그래피파이 등 작업에 도움이 되는 스킬이 이미 설치되어 있으면 관련 지침을 읽고 활용합니다. 목록에 없는 스킬도 작업과 관련이 있으면 활용하며, 스킬이나 실행 도구가 없으면 MemoryMesh의 기본 절차로 계속 진행합니다. 별도 설치를 권하거나 요구하지 않습니다. 회귀 테스트와 웹 화면 검증도 작업에 필요할 때만 수행하며, 실제 도구로 확인하지 못한 부분은 결과에 밝힙니다.

정보, 의견, 개선 가능성 검토나 답변 정리를 요청하면 확인과 답변만 수행합니다. 검토 결과를 자동으로 적용하거나 버전을 바꾸거나 게시하지 않습니다. 다만 그 과정에서 정한 사용자 결정, 이후 작업에 필요한 확인 결과, 합의한 다음 단계는 다음 세션이 이어받을 수 있도록 짧게 기록합니다. 파일 수정이나 작업 실행을 분명히 요청하면 해당 범위의 작업과 필요한 기록 갱신을 수행합니다. 지시와 질문이 섞여 있으면 지시한 부분만 실행합니다.

파일 변경이나 외부 작업 직전에는 최신 요청이 해당 대상과 작업을 승인했는지 확인합니다. 사용자가 “수정이 아니라 검토”라고 범위를 정정하면 그 정정을 우선합니다. 이미 승인된 작업을 매번 다시 묻는 절차는 아니며, 현재 프로젝트 대신 전역 스킬이나 외부 저장소를 임의로 수정하지 않습니다. 승인 범위를 벗어난 변경을 발견하면 해당 작업을 멈추고 알리며, 원본과 이후 변경 여부를 확인할 수 있을 때 자신이 잘못 바꾼 부분만 복원합니다.

실행을 요청한 작업은 완료 기준과 검증 방법을 내부적으로 정하고 바로 진행합니다. 검증 범위는 과거 기록의 분량이 아니라 이번 변경의 위험도에 맞추며, 입력이 그대로인 통과 검증은 반복하지 않습니다. 결과와 필수 검증이 끝나면 기록을 한 번 남기고 마칩니다. 단순한 작업에 별도 계획 파일이나 추가 승인 단계를 요구하지 않습니다.

## 주의할 점과 한계

- MemoryMesh는 에이전트가 따르는 문서 지침입니다. 승인 범위 확인 절차가 있어도 지침 준수를 기술적으로 강제하거나 위반이 절대 발생하지 않는다고 보장하지는 않습니다.
- 기록하기 전에 세션이 갑자기 끊기면 그 사이 대화 속 결정이나 의도는 이어받지 못할 수 있습니다. 파일에 남은 작업 결과는 다음 작업을 시작할 때 확인해 기록을 보완합니다.
- 다른 컴퓨터의 에이전트가 이어받으려면 `.mesh/`와 업무 일지가 동기화나 저장소를 통해 그 컴퓨터에도 있어야 합니다.
- 에이전트 설정에서 프로젝트 지침을 읽지 않게 했거나 파일 저장이 막힌 환경에서는 자동 기록과 재개가 동작하지 않을 수 있습니다. 지침을 읽지 않는 경우에는 에이전트에게 `.mesh/PROTOCOL.md`를 읽으라고 한 번 요청하면 이어서 작업할 수 있습니다.
- 도구가 실행되는 동안에는 에이전트가 진행 안내를 보내지 못해 안내가 늦어질 수 있습니다.
